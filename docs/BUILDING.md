# Building CircleQuickLauncher

Full instructions for building, testing, and packaging the app from source.

## Prerequisites

| Requirement | Notes |
| --- | --- |
| **Windows 10 1809+ or Windows 11 (x64)** | Build/test must run on Windows. |
| **.NET 8 SDK** | [Download](https://dotnet.microsoft.com/download/dotnet/8.0) — includes the Windows targeting pack. |
| **Windows SDK 10.0.17763** (or later) | Ships with Visual Studio 2022 / Build Tools. |
| **Visual Studio 2022 17.8+** *or* Build Tools | Workloads: **.NET desktop development** + **Windows application development** (WinUI). |
| **Inno Setup 6.x** *(optional)* | Only needed to build the installer; skipped automatically if `ISCC.exe` is not found. |

> **Note:** WinUI 3 / Windows App SDK projects require the Windows SDK component even for command-line `dotnet build`. If `dotnet build` fails with `NETSDK1100` or WinUI targets missing, install VS 2022 with the Windows application development workload, or use the VS Build Tools with the same workload.

## Clone & Restore

```powershell
git clone https://github.com/circlequicklauncher/CircleQuickLauncher.git
cd CircleQuickLauncher
dotnet restore CircleQuickLauncher.sln
```

## Build

```powershell
dotnet build CircleQuickLauncher.sln -c Release -p:Platform=x64
```

Output: `src\CircleQuickLauncher\bin\x64\Release\net8.0-windows10.0.17763.0\win-x64\CircleQuickLauncher.exe`

> The app is **self-contained** (`WindowsAppSDKSelfContained=true`, `SelfContained=true`) — no separate .NET runtime install is needed on target machines.

## Test

```powershell
dotnet test tests/CircleQuickLauncher.Tests -c Release
```

All unit tests cover `CircleQuickLauncher.Core` layout math, config storage, and validation. There are **no UI automation tests** (manual verification required for hover/expand behavior).

## Run (unpackaged / debug)

```powershell
dotnet run --project src\CircleQuickLauncher -c Debug -p:Platform=x64
```

The unpackaged app runs directly (no MSIX container). Logs and config:

```
%APPDATA%\CircleQuickLauncher\
  settings.json        # user settings (schema-versioned)
  apps.json            # pinned apps
  icons\               # copied custom PNG icons
  logs\                # startup.log, crash dumps
```

## Package for Release

One command builds everything:

```powershell
.\scripts\Build-Release.ps1
```

Outputs into `artifacts\`:

| Path | Contents |
| --- | --- |
| `artifacts\portable\` | Self-contained publish folder (extract & run). |
| `artifacts\CircleQuickLauncher-<ver>-portable-win-x64.zip` | Zipped portable build. |
| `artifacts\installer\CircleQuickLauncher-Setup-<ver>.exe` | Inno Setup installer (if ISCC.exe found). |
| `artifacts\msix\` | MSIX package (unsigned by default). |
| `artifacts\SHA256SUMS.txt` | Checksums (generated by CI). |

### Manual portable publish

```powershell
dotnet publish src\CircleQuickLauncher\CircleQuickLauncher.csproj `
    -c Release -p:Platform=x64 `
    -p:PublishProfile=Portable
```

Publish profile lives at `src\CircleQuickLauncher\Properties\PublishProfiles\Portable.pubxml` (self-contained, win-x64, folder publish to `artifacts\portable`).

### Manual MSIX build

```powershell
dotnet publish src\CircleQuickLauncher\CircleQuickLauncher.csproj `
    -c Release -p:Platform=x64 `
    -p:WindowsPackageType=MSIX `
    -p:GenerateAppxPackageOnBuild=true `
    -p:AppxPackageSigningEnabled=false `
    -p:AppxPackageDir=artifacts\msix\ `
    -p:UapAppxPackageBuildMode=SideloadOnly `
    -p:AppxBundle=Never
```

> MSIX signing: set `AppxPackageSigningEnabled=true` and provide `PackageCertificateKeyFile` / `PackageCertificateThumbprint` (CI uses secrets).

### Installer

Requires Inno Setup 6 at the default path (`%ProgramFiles(x86)%\Inno Setup 6\ISCC.exe`). The script expects the portable folder at `artifacts\portable\` — run the portable publish first (or use `Build-Release.ps1`, which does both).

## Continuous Integration

- `.github/workflows/ci.yml` — runs on every push/PR to `main`: restore → build → test (x64 Release). Uploads test results (TRX).
- `.github/workflows/release.yml` — runs on `v*` tags: full build + portable zip + MSIX + SHA256SUMS, then creates a GitHub Release with all artifacts attached.

To cut a release:

```powershell
git tag v1.0.0
git push origin v1.0.0
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `NETSDK1100` / WinUI targets not found | Install VS 2022 with **Windows application development** workload (includes WinUI project templates & MSIX tooling). |
| Build succeeds but app exits immediately | Check `%APPDATA%\CircleQuickLauncher\logs\startup.log`. Single-instance mutex may be held — close other instances. |
| Hover doesn't expand (unpackaged) | Ensure the window subclass is attached (see `MainWindow.FinalizeInterop`). On very slow machines, increase the collapse-delay grace or check the 120 ms poll timer. |
| MSIX `SignTool` errors | Set `AppxPackageSigningEnabled=false` for sideload-only builds, or provide a valid cert. |
| Inno Setup skipped | Install Inno Setup 6 to the default path, or edit the `$iscc` paths in `scripts\Build-Release.ps1`. |

## Architecture (quick map)

```
CircleQuickLauncher.sln
├── src/CircleQuickLauncher.Core     # pure logic: models, layout math, storage, validation
├── src/CircleQuickLauncher          # WinUI 3 app: MainWindow, Services, Views, Interop
└── tests/CircleQuickLauncher.Tests  # xUnit tests for Core (66 tests)
```

Key services in `src/CircleQuickLauncher\Services\`:

| Service | Responsibility |
| --- | --- |
| `AppState` | Central state, settings + apps persistence, change events. |
| `AutorunService` | HKCU Run key / MSIX StartupTask read-write. |
| `IconService` | PNG import, validation, per-app icon cache. |
| `LaunchService` | Shell-execute launch targets with error surfaces. |
| `StartMenuCatalogService` | Enumerate `.lnk` entries from Start Menu folders. |
| `TrayIconService` | Shell_NotifyIcon lifecycle + context menu. |
| `WindowService` | Window chrome (borderless, toolwindow, no-activate), DPI/work-area math, composition backdrop. |
